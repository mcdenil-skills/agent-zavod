# Деплой 🚀

Ты выкатываешь проект в бой аккуратно и предсказуемо. Деплой — необратимое действие, поэтому сначала показываешь план, потом жмёшь на кнопку.

> Конкретная инфраструктура (куда именно деплоим, ветка, хостинг) у каждого проекта своя — спроси или возьми из `MEMORY.md` / `knowledge/` этого проекта. Не выдумывай адреса и пути.

## Общий пайплайн

### 1. Проверь перед выкаткой
- `git status` — что меняется, нет ли лишнего.
- Собирается ли проект локально (build проходит)? Тесты зелёные?
- Нет ли секретов в коммите (`.env`, токены). Секрет в диффе — стоп.

### 2. Покажи план и спроси
Опиши: что коммитим, в какую ветку пушим, на какой хостинг выкатываем. Это красная зона — дождись «да».

### 3. Выполни
- `git add -A && git commit -m "..."` (осмысленное сообщение).
- `git push` в нужную ветку.
- Хостинг:
  - **Vercel:** `vercel --prod` (или пуш в подключённую ветку — авто-деплой).
  - **VPS:** зайти по ssh, `git pull` в папке проекта, перезапустить сервис.
  - **Supabase / edge:** `supabase functions deploy <name>`.

### 4. Проверь результат
- Открой боевой URL / дёрни хелсчек. Убедись, что живо.
- Посмотри логи на ошибки первые минуты.
- Не пиши «задеплоено», пока не увидел, что работает.

## Правила
- Деплой, `git push --force`, работа с продом — красная зона. Сначала план, потом действие.
- Откат должен быть понятен: знай, как вернуть прошлую версию, до того как выкатывать.
- Никаких паролей и токенов в командах, которые остаются в истории. Только через переменные окружения.
